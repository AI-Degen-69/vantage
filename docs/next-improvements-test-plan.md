## Workstream 1: Market-data reliability

### Affected routes and services

- `GET /api/stock-batch-quotes` — validates symbols, invokes ordered batch quote retrieval, and returns partial results.
- `stockService.getBatchQuotes` — active-provider URL selection, canonical work keys, in-flight coalescing, partial provider payload fallback, ordering, and cache behavior. Use a provider seam (small injectable fetch/provider functions or a module-level test adapter) so tests never call Yahoo/FMP and can reset NodeCache/in-flight state per test.
- `stockService.getQuote` — per-symbol fallback and negative-cache behavior.
- `stockService.getProfileValidation` — successful, unavailable, not-found, negative-cache, expiry, and recovery behavior.
- `fetchJSON` or its replacement — timeout, HTTP failure, malformed JSON, and diagnostic classification.

### Required deterministic tests

- Stable mode builds `batch-quote?symbols=A,B,C`; legacy mode retains its documented path.
- A complete provider response normalizes valid positive prices and preserves requested order.
- A partial provider response triggers bounded per-symbol fallback only for missing symbols.
- A malformed row becomes `null` and does not erase valid neighboring quotes.
- Provider HTTP failure, timeout/abort, malformed JSON, empty payload, and fallback exhaustion each produce the documented internal classification and safe client response.
- Concurrent identical batch calls share one in-flight operation.
- Equivalent requests with different symbol order share canonical upstream work but each caller receives its own requested order.
- A rejected in-flight promise is removed and a later retry can execute.
- Successful cache entries and short negative/error entries use distinct TTLs; expiry permits recovery.
- Profile unavailable/not-found results retain the correct `unavailable` semantics and do not become a false cached success.
- Route validation covers empty, invalid, duplicate, and over-limit symbols without calling the service.
- Route/service failures never expose `FMP_KEY`, `AV_KEY`, full upstream URLs, or provider response bodies.

### Manual/integration checks

- Optional `scripts/smoke.mjs` run with credentials and network access.
- Confirm before/after metrics for a 30-symbol request: p95 latency, upstream calls, cache hits, fallback count, and quote coverage. Initial implementation gates: at least 50% fewer upstream operations for repeated identical requests, zero duplicate upstream operations for concurrent identical calls, and no regression in successful quote coverage. Capture three cold and ten warm samples; report median and p95 rather than a single run.

## Workstream 2: Insights heatmap quality

### Affected routes and UI

- `GET /api/sector-heatmap` — validates symbols and compact sector metadata.
- `stockService.getSectorHeatmap` — metadata precedence, provider fallback, cache-key separation, and bounded chart fan-out.
- `useSectorHeatmap` and `Insights` — request construction, query-key correctness, stale/partial data, and coverage display.
- `SectorHeatsheet` — loading, empty, success, partial, untagged, error, retry, responsive, and RTL states.
- `aggregateSectorHeatmap` — curated/provider sector precedence and missing-price accounting.

### Required deterministic tests

- Curated sector metadata wins over provider profile metadata.
- Provider metadata fills only symbols missing curated metadata.
- Missing/blank sectors enter `untagged` without being silently dropped.
- Different normalized sector maps create different server/client cache keys.
- Oversized or invalid metadata is rejected safely while symbol validation remains intact.
- Missing prices remain `null` and never become zero contributions.
- Coverage counts, untagged symbols, and partial rows match the requested universe.
- EN and HE dictionaries contain every new key; numeric/ticker values remain LTR in RTL mode.
- UI state table is exercised with loading, empty, success, partial, stale, provider error, and retry inputs.

## Workstream 3: route-level bundle splitting

### Affected routes

- `/`, `/portfolios`, `/stock/:ticker`, `/insights`, `/watchlists`, `/charts`, `/earnings`, and dev-only `/i18n`.
- `client/App.tsx` lazy imports, shared Suspense fallback, and existing ErrorBoundary composition.

### Required checks

- Production build emits route chunks and reduces the initial entry chunk by at least 25% from the recorded 906.71 kB baseline, unless the build shows the dependency is shared and the plan records the measured reason.
- Direct navigation to every production route succeeds after a cold load.
- Browser back/forward and route transitions retain layout providers and language direction.
- Suspense fallback is visible, localized, keyboard-safe, and announced appropriately.
- A simulated lazy chunk failure reaches the existing route error boundary and offers recovery.
- No page import is accidentally left in the initial entry chunk unless intentionally shared.

